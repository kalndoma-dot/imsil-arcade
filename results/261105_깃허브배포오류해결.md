# GitHub Pages 배포 장애 원인 분석 및 해결 가이드 보고서
본 보고서는 GitHub main 브랜치 배포 과정에서 자주 발생하는 대표적인 오류 유형(404 에러, 파일 경로 누락, Jekyll 한글 처리 충돌 등)의 원인을 분석하고 즉시 조치할 수 있는 해결책을 정리한 문서입니다.

## 1. 대표적인 문제 유형 및 해결 방안
- **유형 1: 404 Not Found (사이트가 전혀 열리지 않음)**
  - 원인 A (폴더 중첩 구조): GitHub 저장소에 올릴 때 `Vibe Coding` 폴더 자체를 통째로 올려서 `index.html`이 최상단(루트)이 아닌 `Vibe Coding/index.html` 하위에 위치한 경우. GitHub Pages는 저장소 최상단 루트의 `index.html`만 인식합니다.
    - 해결: 저장소 메인 화면에 들어갔을 때 `index.html`과 게임 파일들이 폴더 없이 바로 보이도록 업로드해야 합니다.
  - 원인 B (Pages 설정 누락): 파일만 push하고 GitHub Pages 설정을 켜지 않은 경우.
    - 해결: GitHub 저장소 상단 `Settings` > 좌측 `Pages` > Branch를 `None`에서 `main` / `/ (root)`로 변경 후 `Save` 버튼을 클릭합니다.
  - 원인 C (빌드 대기 시간): 설정을 켠 직후에는 빌드 중이므로 약 1~3분 후 접속해야 합니다. 저장소 상단 `Actions` 탭에서 초록색 체크가 뜨면 완료된 것입니다.
- **유형 2: 메인 화면은 뜨는데 게임 클릭 시 404 에러 (한글 파일명 충돌)**
  - 원인: GitHub Pages의 기본 빌드 엔진인 Jekyll이 한글이나 공백이 들어간 파일명을 처리하는 과정에서 링크가 누락되는 현상.
    - 해결: Jekyll 빌드를 끄는 빈 파일인 `.nojekyll` 파일을 저장소 최상단 루트에 함께 올려주면 순수 정적 웹 호스팅으로 전환되어 모든 한글 파일이 정상 열립니다. (현재 로컬에 `.nojekyll` 파일 생성 완료)
- **유형 3: 파일명 끝 공백으로 인한 링크 오류**
  - 원인: `이승아 별이반짝이는 밤 .html` 파일명 끝에 공백이 있어 리눅스 호스팅 환경에서 주소 인코딩 불일치 발생.
    - 해결: 파일명을 `이승아 별이반짝이는 밤.html`로 정리하고 `index.html` 링크를 정상 반영했습니다.

## 2. 체크리스트 및 점검 순서
- 저장소 메인 페이지 첫 화면에 `index.html` 파일이 바로 존재하는지 확인.
- 저장소 메인 페이지에 `.nojekyll` 파일이 함께 올라가 있는지 확인.
- 저장소 `Settings > Pages`에서 `Branch: main / (root)`로 저장되어 있는지 확인.
- 상단 `Actions` 탭에 방문하여 `pages-build-deployment` 작업이 초록색(Success)인지 확인.
